# UED WorkBuddy桌面版（原型 · 2026-09-10）

给产品、设计共用的AI工作台（2026-09-16 吉吉定：去掉「前端」这一栏，前端只作为交付接收方出现在「发给前端」里）。**引擎是同事自己电脑里的Claude Code**（席位、代理、上报都跟平时敲 `claude` 一样），飞鹊设计系统随应用携带，产物落成文件、右侧实时预览，做完一键发给前端。

## 跑起来

```bash
cd desktop
npm install            # 只有 electron 一个依赖
npm start
```

如果Electron二进制下载失败（公司代理直连GitHub会被掐），用国内镜像补一次：

```bash
ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/" node node_modules/electron/install.js
```

前提：这台电脑上装了Claude Code并登录过（终端里能敲 `claude`）。应用按这个顺序找：`~/.fcf/bin/claude`（公司FCF启动器，优先）→ `~/.local/bin` → Homebrew → nvm。

## Claude是怎么接的（实测判据）

```
claude -p --input-format stream-json --output-format stream-json --verbose \
  --include-partial-messages --permission-mode acceptEdits --permission-prompt-tool stdio \
  --add-dir <packs/feique> <~/.claude/skills> --append-system-prompt <一段 UW 上下文> --session-id <uuid>
```

- **不加任何锁**：skill / MCP / hooks / CLAUDE.md / memory全在。这就是「终端里的Claude能力都有」。
- **权限**：必须带 `--permission-prompt-tool stdio`，而且进程一起来就先写一条 `initialize` 的 `control_request`，之后Claude每次要动手都会发 `can_use_tool`，应用弹卡让人点「允许 / 拒绝 / 本次任务全部放行」。少了握手Claude会直接 `permission_denied`。三档：每步都问 / 改文件自动放行跑命令问（默认）/ 全部放行。
- **FCF启动器**会先往stdout打彩色横幅，只认以 `{` 开头的行。
- 续聊：进程常驻，同一个stdin继续写user消息；关掉应用再打开，用 `--resume <session_id>` 接上。

## 像 Figma 那样直接改预览（2026-09-16 加）

预览栏右端「编辑」→ 出工具栏和右侧属性面板。单击选中（蓝框 + 尺寸标签）、双击改字、按住拖动在同级之间换顺序、拉右下角手柄改宽高；面板改字号 / 字重 / 对齐 / 颜色 / 填充 / 宽高 / flex 布局 / 内外边距 / 描边圆角 / 透明度，字号和圆角只给飞鹊阶梯，色板只给飞鹊 token（也能手填，不在色板里的标橙）。快捷键：⌫ 删 · ⌘D 复制 · ⌘↑⌘↓ 前后挪 · ⇧Enter 上一层 · Tab 下一个 · ⌘Z / ⇧⌘Z 撤销重做。

**改动直接写进 HTML 文件，不经过 Claude。** 下一次对话时会把这期间的手改清单塞在消息前面告诉 Claude，免得它按旧印象改回去。

怎么做到的（三个文件）：
- `main/htmlmap.js` — 给源码里每个开标签按顺序编号（`data-uw-i`，只加在送去预览的副本上，磁盘文件不动），预览里报「第 N 个元素怎么改」，这里用同一套分词器重新数一遍源码原地补丁。样式改成内联 `style`，文字替换要核对旧文字，删 / 复制 / 挪位置整行连缩进一起搬。`<li>`、`<p>` 这类没写闭合的按浏览器规则算隐式闭合，只许改样式和文字。
- `main/edit-probe.js` — 注进预览页的编辑层（选框、悬停框、拖拽插入线、手柄、快捷键），只对带编号的元素生效；脚本运行时生成的元素点到会说「这块是脚本生成的」。
- `renderer/app.js` 末尾「编辑层」与「飞鹊组件栏」两节 — 工具栏、属性面板、撤销重做、手改记录、组件栏与组件属性。
- `main/components.js` — 飞鹊组件清册（见下一小节）。样式和文字改完不重载（DOM 已是新的），结构性改动重载并按新编号恢复选中。

判据：撤销前会核对文件是不是我们上次写出去的样子，中间被 Claude 改过就先提示、再按一次才连着退；`fs.watch` 在我们自己写完文件后会想重载预览，2.5 秒内压掉，不然选中会被冲掉。

**收起对话**：工具栏最左、返回箭头旁的侧栏开关（跟 Finder 一个位置，⇧⌘\ 也行）。对话区整个收掉、画布吃满；收起时开关高亮，右上角挂状态点：Claude 在跑＝蓝色呼吸、跑完没看＝橙色。再点一下展开。跟「只看对话」互斥。（第一版做成左边缘竖排「对话」把手，吉吉说丑、且入口不该在编辑工具栏，当天改掉。）

**附件进对话**：把文件或图直接拖进对话区（拖入时整栏盖一层蓝色虚线蒙层）、在输入框 ⌘V 粘贴截图、或点回形针选文件。文件拷进项目的 `附件/` 目录（Claude 只读得到项目目录里的路径，也顺带进交付包），在输入框上方摆成小卡，随下一条消息发出去：正文末尾列出路径，图片标「用 Read 工具直接看」，界面只显示原话＋📎 名字。从浏览器拖来的图没有本机路径，按粘贴存文件。拖进来的 File 拿路径必须走 `webUtils.getPathForFile`（`File.path` 在 Electron 32 起没了）。首页输入框也能拖，项目还没建就只写路径。

编辑态工具栏最左「飞鹊组件」→ 左侧出组件栏（像 Figma 的资产面板）：14 个控件（按钮三种 / 输入框 / 搜索框 / 标签两种 / 徽标两种 / Tabs / 分页 / 提示条两种 / 开关）＋ 12 个页面片段（六种产品卡 / 两种 MIC 页脚 / VO 顶栏、二级导航、左侧栏），每张卡带真渲染的缩略图，可搜索。

## 多页面流程：控制台是另一个窗口（2026-09-17 加）

吉吉的长远目标是拿 UW 替代 Figma —— 给 PRD、直出 HTML 给前端。多页面是这条路上第一个绕不开的坎：
一个需求上到十几个页面、每页六七个状态之后，「有没有漏」就不能靠人点一遍了。

他的三条输入定了整个做法：**一个需求上百页（大多是状态不是页面）· 自己走查也给外部展示 · 前端拿到的不只是 HTML，还要自带交互流程说明，人和 AI 都能读**。

### 先把 100 拆成两种东西

| | 是什么 | 怎么看 |
|---|---|---|
| **页** | 有独立地址、能被跳到的 | 流程视图（十几个节点，画得出也看得懂） |
| **态** | 同一页的空 / 满 / 错 / 未登录 / 加载 | 对照表横着比，**不进流程图** |

把态画进流程图是「100 页变一团毛线」的唯一原因。拆开之后，流程图只剩十几个节点，
态在「页 × 态」的对照表里一屏看完 —— 而且那张表自己就是覆盖清单，**空格子就是还没做的**。

🔴 **Figma 到这个量级也不是靠铺开**：100 个画板缩到能看全貌时每个只有指甲盖大，
真正在用的是图层面板那列名字和 ⌘P。所以这里不复刻画布，对标的是「命名 + 检索 + 关系」。

### 三条地基约定（改这三条 = 所有视图一起返工）

1. **状态是页面级的，落在根节点的一个类上**：`<body class="state-empty">`，CSS 里写 `body.state-empty .list{display:none}`。
   为什么是类不是文件：重复率高，15 个页面拆成 100 个文件之后改一次页头要改 100 遍。
   还有个白捡的好处 —— **控制台在 iframe 外面换这个类就能切态，页面里一行 demo 代码都不用留**。
   那些 `state-*` 类本身就是前端要用的真实状态类，不是脚手架。
2. **说明住在页面旁边**：`index.html` → `index.说明.md`。人只写机器扫不出来的那部分（为什么、什么时候、校验规则）；
   页面清单、跳转矩阵、状态清单全部从代码扫。
3. **主线写在项目根的 `剧本.md`**：一个二级标题一条线，步骤是 `页面 · 状态 · 说明`。
   给外部展示走的是**路线**不是地图 —— 100 页丢给对方自己点，他会点进半成品、点进死路。

### 七道判漏的门（`main/flow.js`，都从代码真值算，没有一条靠人声明）

断链 · 孤儿（谁都跳不到它）· 死路（进去出不来）· 状态说了没做 · 状态做了没说 · 说明对不上页面 · 字段没规则。
另加剧本指向不存在的页 / 态。**单页项目不跑孤儿和死路** —— 门在不该说话的时候说话，人就会开始忽略它。

### 控制台为什么是另一个窗口

吉吉原话：「那种 demo 控制台我不想做在页面里，那样没有沉浸式体验」。
画在页面里还有个更硬的理由：**那段脚手架会跟着交付给前端**。
做成主窗口里的一条边栏也不行 —— 边栏会把预览挤窄，响应式断点当场失真。
所以控制台自己一个窗口（默认贴主窗口左边），页面那个窗口 100% 是页面。

入口在预览栏的「流程」按钮。四个视图各管一件事：**对照表**（有没有漏）· **流程**（怎么走）·
**剧本**（给外部走哪条线）· **检查**（七道门的结果，点一条直接跳到那一页）。
「展示模式」= 主窗口进「只看画布」，控制台只剩上一步 / 下一步（方向键也能翻，Esc 退出）。

代码：`main/flow.js`（扫描 + 门）· `main/flow-doc.js`（交付说明编译）· `renderer/flow.{html,css,js}`（控制台窗口）·
`main/main.js` 的 `flow:*` 一节（窗口与转发）· `main/edit-probe.js` 的 `case 'state'`（换类，**绝不写文件**）。

### 交付给前端的那份说明

发给前端时自动多两份：`交互流程说明.md` 和 `flow.json`，**同源**。

🔴 「给 AI 读」不等于「输出 JSON」。读文档时最怕的不是格式不结构化，是**找不到对应位置** ——
说明里写「点击立即询盘后校验手机号」，得在十几个页面里猜哪个按钮是它，猜错了就开始编。
所以两条硬要求跟格式无关：**可定位**（每条规则指得到真实选择器，`class="btn inq-btn"` 出的是 `a.btn.inq-btn`
不是 `a.btn`，否则两条跳转指到同一个选择器）· **可核验**（说明里提到的选择器页面里必须真的存在，spec-drift 门盯着）。

一份文件两层内容，不出两份（两个维护源必打架）：**契约层**（页面清单 / 跳转矩阵 / 状态清单 / 字段规则，全部机器生成）
＋ **意图层**（为什么这么设计，人写在各页的 .说明.md 里，原样搬过来）。
第五节是「交付时还没闭合的地方」，**故意不藏** —— 藏起来前端会把没做完的当成设计本身照着实现。

### 铺开：所有状态并排看（2026-09-18 加）

控制台第二个标签「铺开」。**对照表回答「有没有漏」，铺开回答「长什么样」** —— 圆点只告诉你这一格做了，
做成什么样只有看见才知道。两种摆法：这一页的所有状态 / 所有页面。点任一张在主窗口里沉浸看。

缩略图是**真页面按 1240 宽渲染再 `transform:scale` 缩小**的，不是截图 ——
做小 iframe 会触发响应式断点，量到的就不是它在 1240 下真正的样子。
格子高度按页面**内容真实底边**裁（不是 `scrollHeight`，那个至少等于视口高，短页面底下永远拖一片白）。
进这个标签控制台窗口会自动撑宽，离开还原。

### 🔴 demo 控制条不许做在页面里（2026-09-18 吉吉焊死）

原话：「我希望做需求的时候，demo 控制台不要做在页面里，而是放在独立控制台里」。
两条理由，第二条更硬：① 页面里挂一条工具栏，评审和给外部看的时候没有沉浸感；
② **那段东西会跟着交付给前端**，他还得自己判断哪些是产品、哪些是演示脚手架。

- **以后**：`packs/feique/DESIGN.md` 第 6 节第 5 条写死；飞鹊体检 `demobar-in-page` ＋ 流程门同名那条，都判**硬伤**。
- **存量页面**：扫描器认得出（类名像 `demobar`、或明写了「Demo 控制台」），把里面的选项读出来报在「检查」里，
  告诉你有几个场景要转成 `state-*`。**不去驱动它** —— 花力气驱动等于维持这个要消灭的形态，改一次就顺了。

### 飞鹊缺省图：31 张，别再留灰方块（2026-09-18 加）

### 给外部展示的两条路（都要，别只做一半）

- **你自己驱动着演示** → 控制台的「展示模式」：主窗口只剩画布，控制台只剩上一步 / 下一步。
- **对方自己点** → 控制台的「导出走查包」出一个独立的 `_走查.html`（发给前端时也会自动带一份）。
  对方没装 UW、双击就能开，顶上一条控制条（选页面 / 选状态 / 走主线 / 只看页面），按 H 或 Esc 收放控制条。

🔴 **走查包把每个页面整份内联进 `srcdoc`，不是 `src=` 指过去**：对方是 `file://` 打开的，
那里 Chrome 一律禁止跨文档访问，用 `src=` 的话「在 iframe 外面换状态类」当场就废。
`srcdoc` 继承父文档的源才成立。代价是文件大一些（每页一份拷贝），子目录页面靠补 `<base>` 保住相对路径。
这一份是**交付时生成的产物不是维护源**，页面改了重新导一次。

## 更新怎么到同事那边（2026-09-16 加）

不签名（开发者账号先不采购），macOS 上 electron-updater 那种静默自更新做不了，所以走「查到就提示、点一下自己换」：

- **发版**：改 `package.json` 的 version → `build/release.sh "更新说明"`（dmg 已经打好且验过可加 `SKIP_BUILD=1` 直接发）。🔴 bash 里 `$VAR` 后面紧跟全角括号会被当成变量名的一部分（`$TAG（` → `TAG（: unbound variable`），脚本里一律 `${VAR}`。脚本打包、核对包内代码与源码一致、`gh release create desktop-vX.Y.Z` 挂上 dmg，最后用客户端同一套挑版本逻辑核对 GitHub 上那条能被认出来。tag 前缀 `desktop-v` 是客户端认的，网页版与桌面版共用一个仓库靠它分开。
- **客户端**（`main/updater.js`）：启动 3 秒后查 GitHub Releases 列表，挑 `desktop-v` 最高的一条、按平台取包（Mac 取 universal dmg，Windows 取 `-win-x64-setup.exe`，见 `ASSET` 表）；有新版右上角浮出一张 macOS 系统更新式的小卡（标题 / 当前版本与体积 / 第一条说明 / 以后再说 / 更新，下载时卡内进度条）。2026-09-16 在吉吉机上 0.1.26 → 0.1.29 一键换包跑通。点「现在更新」→ `net.fetch` 下到 `~/.uw-desktop/updates/`（走系统代理，同大小已存在就复用）→ 写 `install.sh` 脱离进程跑：等本进程退出 → 挂 dmg → `ditto` 覆盖 .app（先备份，失败回滚）→ `xattr -dr com.apple.quarantine` → 弹出 → `open -a`。日志在 `~/.uw-desktop/updates/install.log`。
- **护栏**：有会话在跑不给换（换包要退出应用），再点一次才强制；「这次先不更」记住版本不再弹；设置里有「检查更新」。
- 🔴 判据：换包脚本用真 hdiutil / ditto / xattr 对着假 .app 排练过（`_verify/edit/updater.test.js`），包括等旧进程、回滚、dmg 里没 .app。**真机换包只能靠下一次发版验**。
- **Windows 那半（2026-09-17 加，0.1.46）**：同一条链，包换成 NSIS 一键安装包，换包脚本换成 PowerShell（`installScriptWin`）：等旧进程退 → `setup.exe /S` 静默装回原位置（NSIS 先卸旧的）→ 重开。下载落盘不带 Mark-of-the-Web，所以静默跑不会被 SmartScreen 拦；只有同事**第一次手动双击安装包**会弹一次 SmartScreen。🔴 **Windows 这条链只在 Mac 上假装成 win32 跑过纯逻辑门（`_verify/edit/win.test.js`），没有在真 Windows 机器上点过**。

## 打包分发

```bash
npm run dist          # Mac：dist/UED-WorkBuddy-<版本>-universal.{dmg,zip}
npm run dist:win      # Windows：dist/UED-WorkBuddy-<版本>-win-x64-setup.exe（在 Mac 上就能打，electron-builder 26 用 resedit 改 exe 资源，不用 wine）
build/release.sh "说明"   # 两个都打 + 核对包内代码与源码一致 + 发 release；SKIP_WIN=1 只发 Mac
```

没有苹果开发者证书，`build/afterPack.js` 会打一个本机临时签名，同事首次打开要右键「打开」或在系统设置里「仍要打开」一次。Windows 包同样没签名，同事第一次双击会弹 SmartScreen，点「更多信息 → 仍要运行」一次。
Windows 打包工具（makensis / winCodeSign / 图标包）从 GitHub 拉，公司网络掐 GitHub 时设 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`（release.sh 里已默认）。飞鹊包、知识库、向导数据按 `asarUnpack` 解在 `app.asar.unpacked/packs/`，因为拉起的Claude是外部进程，读不到asar里的文件。同事版安装步骤见 `安装说明.md`。

## 一键发给前端做了什么

1. 把项目里的产物（跳过 `.uw` / `.git` / `node_modules`）复制到 `~/UW工作区/_交付/<时间>-<项目>/`，加 `manifest.json`，`ditto` 打成zip。
2. 在交付仓库开分支 `handoff/<时间>-<项目>`，把包放进 `<项目>/`，提交；仓库有origin就push并生成合并请求链接（GitLab / GitHub两种）。
3. 生成「给前端的话」（入口文件、交付说明、分支或链接、怎么用UED WorkBuddy接收）放进剪贴板，直接粘到飞书。
4. 前端在同一个应用里选「前端 → 接收交付包并还原」，Claude读 `交付说明.md` 落成组件代码。

项目里没有 `交付说明.md` 时会先提示「先整理交付说明」，那是一条能力卡，Claude会把页面结构、状态清单、token对照、交互决策的为什么写全。

## 字体字重焊死（2026-09-17 加 · 0.1.48）

只写 `font-family: Roboto, …` 不够：浏览器拿到 `font-weight:400` 要去系统已装的 Roboto 家族里挑一张脸，
装了多个静态 Roboto 的机器上 **Chrome 挑中的是 Roboto-Black(900)**，而中文回落 PingFang SC Regular(400)
—— 同一行字差 5 个字重档，看起来就是「英文数字比中文粗」。

🔴 **这个 bug 是机器相关的**：没装 Roboto 的同事完全看不到，所以同一份 HTML 在不同人机器上长得不一样。
🔴 **光看 computed style 查不到**：它只说明你要了 400，不说明浏览器给了你 Black。要用 CDP 的
`CSS.getPlatformFontsForNode` 读实际落地的 PostScript 名。

做法：`packs/feique/fonts/` 里放着**线上正在用的那两份** Roboto（从线上 VO 页的 @font-face 逐字节取的），
`main/feique-font.js` 在**预览刷新**（`files:check`）和**交付打包**（`handoff.js`）两个时点自动内嵌进 HTML。
幂等、带 `UW-FEIQUE-FONT` 标记、克隆线上的页面不碰（它自带线上那 24 条）。页面 +46KB。
体检 `font-pin` 规则兜底：没焊死判硬伤。门在 `_verify/edit/font.test.js`（29 项，含 5 项真 Chrome 渲染）。

换 `fonts/*.woff2` 要重导 `coverage.json`（体检的 `glyph-range` 拿它当判据），font 门会核字节数。
