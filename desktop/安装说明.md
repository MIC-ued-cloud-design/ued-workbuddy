# UED WorkBuddy桌面版 · 安装说明（同事版）

一共三步：确认电脑上有Claude Code，装应用，第一次打开放行一次。

## 1. 先确认Claude Code能用

打开终端，敲：

```
claude --version
```

能看到版本号（比如 `2.1.267`）就行。看不到的话，按部门发的FCF安装说明装一遍Claude Code并登录，登录用公司的Claude Team账号。UED WorkBuddy自己不接模型，用的就是你电脑里这份Claude Code，所以它没装好应用打不开会话。

## 2. 装应用

拿到 `UED-WorkBuddy-0.1.5-universal.dmg` 一个文件就够了，Apple芯片和Intel芯片的Mac都能装。

双击dmg，把UED WorkBuddy拖进「应用程序」文件夹。

## 3. 第一次打开要放行一次

这个包没有苹果开发者签名，系统第一次会拦。两种办法任选：

- 在「应用程序」里**右键点应用 → 打开**，再点一次「打开」。
- 或者双击后弹出「无法打开」，去 系统设置 → 隐私与安全性，最下面点「仍要打开」。

只需要做一次。以后从启动台或应用程序里正常双击就行。

如果提示「文件已损坏」，在终端里跑一句再打开：

```
xattr -cr "/Applications/UED WorkBuddy.app"
```

## 打开后

- 左下角显示「Claude Code x.x.x」绿点，说明接上了。红点就是没找到Claude Code，看下面那节。
- 首页选角色、选场景、写需求、发送，项目会建在 `~/UW工作区/` 里，每个项目一个文件夹。
- Claude要跑命令时会弹卡问你，改文件默认自动放行。想改档位在左下角「设置」。
- 做完点右上角「发给前端」，交付包会落在 `~/UW工作区/_交付/`，「给前端的话」自动进剪贴板，粘到飞书就行。

## 红点：显示「没找到Claude Code」

终端里 `claude --version` 明明有，应用里却是红点 —— 0.1.1之前会这样，原因是从访达启动的应用拿不到你终端里的PATH，公司FCF的claude脚本在那种环境下跑不起来。**0.1.1已经修了**：应用会去问你的登录shell要真实环境。

要是0.1.1还红：

1. 点左下角那个红点打开设置，里面「引擎」那块可以直接填claude的位置 —— 终端里敲 `which claude` 把路径抄进去，点「重新检测」。
2. 还不行就点「复制诊断信息」，把内容发给吉吉。也可以直接把 `~/.uw-desktop/diagnostics.json` 这个文件发过来，里面写了它找过哪些位置、每处为什么没成。

## 用量

跑的是你自己Claude Team席位的额度。Opus一档比Sonnet费约5倍，日常建议在首页输入框右下角把模型切成Sonnet，出稿定稿再换。

## 卸载

把「应用程序」里的UED WorkBuddy拖到废纸篓。项目文件在 `~/UW工作区/`，设置在 `~/.uw-desktop/`，要清干净就一起删。
