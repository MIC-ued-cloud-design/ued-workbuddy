# 飞鹊设计系统（MIC · Made-in-China.com前台）· 引擎速查版

> 这份是UED WorkBuddy桌面版随应用携带的飞鹊设计系统。做任何MIC / 飞鹊界面之前先读完这一页；
> 数值以本目录 `tokens.json` 为准，用法与判断以 `docs/飞鹊组件使用经验和规范.md` 为准（51KB，做视觉稿必读一遍）。
> 图标：本目录 `icons/` 共295个SVG（文件名即图标名，清单见 `icon-variants.txt`），一律内联SVG，不要用字体图标、不要自己画。
> 组件清册：`web-components.json`（Web 44页）/ `mobile-components.json`（移动端）。有Figma MCP时按key取真组件，认key不认名。

## 1. 字体与字号

- 字体只用 **Roboto**（CJK自动回落系统字体）。禁Noto Sans SC / PingFang显式声明。HTML里写 `font-family: Roboto, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;`
- 字重只有 **400 / 700**，700只给标题和一级信息。
- Web字号阶梯（禁奇数，就近取偶）：`12 · 14 · 16 · 18 · 20 · 22 · 24 · 32 · 36`
  - **14px是默认**（正文、按钮、导航、输入框、标签、参数、面包屑）行高22
  - 16区块标题 / 24；18小屏标题 / 26；22副标题 / 28；24区块大标题 / 30；32大屏标题、价格 / 38；36页面主标题 / 42
  - 12只给真正不重要的注释（角标、底栏辅助说明）行高18
- 移动端阶梯：`10 · 12 · 14 · 16 · 18 · 20 · 22 · 24`（16是输入框主文字）
- 层级靠**颜色深浅**建立，不靠缩小字号。

## 3. 间距（4px网格）

水平间距严格只用7个token：`4 · 8 · 12 · 16 · 24 · 32 · 48`（xxs / xs / s / m / l / xl / 2xl）。
垂直间距优先用这7个，不够时允许20 / 28 / 36 / 40等4的倍数；禁5 / 10 / 15 / 25 / 30。
间距是层级信号：同级同间距，不同级拉开；不为塞内容压间距。

## 4. 圆角、描边、阴影

- 圆角实测：输入类 / 小控件 / 标签 **4** · 按钮 **6** · 表单卡片 **8** · 大卡片 **12** · 模态 **20** · 胶囊9999。外圆角 = 内圆角 + padding。圆角不随断点变。
- 描边宽度只有 **1 / 2**，描边一律inside。
- 阴影三级，要么全用要么全不用：
  - 1级（下拉、hover浮起）`0 5px 12px 4px rgba(0,0,0,.08), 0 3px 6px 0 rgba(0,0,0,.12), 0 1px 2px -2px rgba(0,0,0,.10)`
  - 2级（卡片hover、浮层）`0 9px 28px 8px rgba(0,0,0,.05), 0 6px 16px 0 rgba(0,0,0,.08), 0 3px 6px -4px rgba(0,0,0,.12)`
  - 3级（对话框、抽屉、通知）`0 12px 48px 16px rgba(0,0,0,.03), 0 9px 28px 0 rgba(0,0,0,.05), 0 6px 16px -8px rgba(0,0,0,.08)`

## 5. 按钮层级

实心红 `.btn-primary` → 主CTA（Send Inquiry等），**全页只有一个** · 次级 `.btn-secondary` → **白底 #222黑边黑字**（不是红描边——飞鹊按钮矩阵里根本没有「红描边」这个变体，`secondary+red` 的意思是「跟红主按钮配对的次级」）· 蓝描边 `.btn-secondary-blue` → 第三级（TM聊天）· 灰底灰边 `.btn-secondary-dark` → 工具性弱操作（筛选、排序）· 文字链 `.btn-link` → 页内跳转类动作。
浮层里的「确定 + 取消」＝ `.btn-primary` ＋ `.btn-secondary`，不能用灰按钮做取消。
🔴 2026-09-10反例：一页里2个实心红 ＋ 6个红描边 ＋ 一堆红tag，再加一个飞鹊没有的 `.btn-neutral`——每个色值都在表内，整页却不是飞鹊。**颜色合法不等于组件合法。**

## 5b. 做网页时组件从哪来（写第一行CSS之前先看这里）

飞鹊组件在网页里的**实现**已经按组件切开成一类一个文件，清单是 **`docs/css/INDEX.md`（砖表）**——28类、加起来73KB，挑要用的`cat`进`<style>`即可。（权威源仍是 `docs/飞鹊Web组件库.css`，砖表是它的切片、内容一样；那份里另有509KB是图标data-URI，组件不依赖。两边与Figma不一致时以Figma为准。）用法铁律在 `docs/飞鹊组件使用经验和规范.md` 第零、一节：**参考页面只学布局和信息层级，实现一律用飞鹊的砖，绝不从参考页抄样式值。**

| 组件 | 类名 | 规格（以CSS为准） |
|---|---|---|
| 按钮尺寸 | `.btn` ＋ `.btn-lg` / `.btn-md` / `.btn-sm` | 40/8 · **32/6（默认）** · 24/4（高/圆角），lg字号16，其余14，字重400 |
| 按钮变体 | `.btn-primary` `.btn-primary-blue` `.btn-primary-dark` `.btn-secondary` `.btn-secondary-blue` `.btn-secondary-dark` `.btn-dashed*` `.btn-text` `.btn-link` `.btn-round` | 见 §5层级；没有别的变体，别发明 |
| 输入框 | `.inp` ＋ `.inp-body` ＋ `.inp-lg/.inp-sm` ＋ `.inp-error/.inp-warning/.inp-success/.inp-disabled` | 1px `#CED3D9`，圆角4（lg为8高40），hover `#888` |
| 提示条 | `.alert` ＋ `.alert-sm/.alert-lg` ＋ `.alert-error/-info/-success/-warning` ＋ `.alert-icon/.alert-body/.alert-msg/.alert-link/.alert-close` | 圆角8；**没有按钮槽位，动作是 `.alert-link` 文字链** |
| 标签 | `.tag` ＋ `.tag-line-*` / `.tag-areal-*` | 12/18，圆角4 |
| 其余21类（分页/下拉/级联/勾选/单选/开关/数字输入/文本域/上传/步骤条/抽屉/折叠/Tabs/列表/面包屑/气泡/全局提示/加载/骨架/空状态/滚动条/徽标） | `.pg*` `.sel*` `.cscd*` `.cb*` `.rd*` `.sw*` `.inp-num*` `.ta*` `.upl*` `.stp*` `.dw*` `.clps*` `.tab*` `.lst*` `.brd*` `.tip*` `.msg*` `.spin*` `.skel*` `.empty*` `.scr*` `.bdg*` | **每类一个文件，见 `docs/css/INDEX.md`** |
| 投影 | `.shadow-1/-2/-3` | 三级，全用或全不用 |
| **价格** | 不是组件，是写法规范：`docs/MIC英文价格规范-AI友好型.md` | `US$15.20-16.60`（US$ 后不空格、区间短横）· 起订量 `100 Pieces (MOQ)`（不写Min. Order）· 单位与数量之间一个空格 |

**做法**：开工第一步先读 `docs/css/INDEX.md` —— 那是飞鹊28类组件的网页实现清单（砖表）。看这一页要用哪几个，就 `cat docs/css/{_reset,btn,inp,…}.css` 读出来（一律带上 `_reset.css`；28个全抄也才73KB），**把读到的内容原样贴进 `<style>`**。🔴 **别重定向到文件**（`> x.css`）——那样内容根本没进你眼里，只会凭印象重写出一版尺寸全错的。🔴 贴完**不许改里面的值**（高度/圆角/padding/字号/hover色都是定死的）。类名保持飞鹊的（前端拿到能一眼对上）。🔴 **不许自己另写一套 `.btn` / `.inp` / `.alert`，不许借飞鹊前缀造飞鹊没有的类**（`.btn-neutral`、`.btn-blue` 这种）。组件的高度、圆角、描边、字号以 `css/` 里的为准，本文件只管颜色与排版口径。
🔴 **砖表里没有的那25个是业务组件**（ProductCard八个变体、MIC Footer页脚、FilterSidebar、Supplier Ad、TM Bar、vo-header/nav/sider、mic-logo）——它们只有Figma、没有CSS实现，却恰恰是MIC真实页面的主力。清单带Figma key在 `INDEX.md` 末尾，用 `download_assets` 按key导出真资产；导不到就留灰色占位块并写明「待补真资产」，**别手画**（见第7节）。
🔴 就算用户没说「还原」，只要做的是MIC线上已有的页面类型（询盘、搜索、产详、发送成功页、登录注册…），先用chrome-devtools打开线上同类页看一眼，再动手——参照物先于灵感。

## 6. 视觉原则（死命令）

1. 统一性：混乱不是丰富。装饰能省则省，投影全用或全不用，同类交互反馈必须一致。
2. 层级三工具按优先级：颜色深浅 → 字重 → 字号。
3. 信息精简，空间感是层级的一部分。
4. 图标只用飞鹊295个SVG；缺省图在 `docs/` 同级 `sprites`（本包未带，需要时留空占位块 `#F0F1F2`）。
5. 「算对了」不等于「做对了」：写完自己在1240与375两个宽度下看一遍。
6. 🔴 品牌标识不许自己画，见第7节。手画的LOGO是最容易蒙混过关、也最丢人的一类错。

## 7. 品牌资产（🔴 一律不许自己画）

**MIC LOGO就在这个包里：`brand/mic-logo.svg`**（240×46，取自飞鹊组件库 `mic-logo`，key `16b912f2a723fc29a132f2c1b05fae23cc2c25b0`，节点4596:1086）。直接内联进页面，按比例缩放，不要重画、不要用文字拼、不要换字体。

- 🔴 **品牌红是 `#DA291C`，不是主色 `#E64545`。** 这两个是不同的红：`#E64545` 是界面主色（按钮、强调），`#DA291C` 只属于LOGO。LOGO的颜色**允许硬编码、不绑Paint Style、不许被override**。
- 🔴 **295个图标里那个 `mic.svg` 不是LOGO**，它是16×16单色 `#222` 的M字标图标，用在列表、标签这种小尺寸场合。拿它当页头LOGO是错的。
- 🔴 **凡是品牌标识（LOGO、商标、认证标、支付标），拿不到真资产就留占位块并在交付说明里写明「待补真资产」——绝不允许照印象手画一个近似的。** 画出来的东西看着像那么回事，反而没人会去核，最后就这么发出去了。
- MIC的页头、页脚、导航同理：这些是**既有的**，属于复刻范围，不是设计空间。做任何MIC页面之前先确认页头页脚取哪一族（飞鹊有5族页头 + 3族页脚，高度各不相同）。

### 要放一个现成元素时，按这个顺序找

0. **做网页先看砖表 `docs/css/INDEX.md`**（§5b）—— 28类组件有现成CSS，挑要用的整段抄；清册是Figma坐标、不是网页实现。砖表里没有的那25个业务组件（产品卡/页头页脚/筛选侧栏/LOGO）才往下走第1步。
1. **组件清册 `web-components.json`**（移动端 `mobile-components.json`）—— 按钮、输入框、卡片、**页头页脚、LOGO、认证标**都在里面，每条带Figma的key和节点号、尺寸、颜色规则。**这是第一站，不是最后一站。**
2. **`brand/` 目录** —— 品牌标识的现成SVG，直接内联。
3. **`icons/` 目录** —— 295个UI小图标。

🔴 **别只搜 `icons/`。** 那里只有UI图标；LOGO、页头这类在清册里。2026-09-10实测过一次反例：模型13次打开这个包，每次都只在 `icons/` grep图标名，从没想到去清册查LOGO，最后自己画了一个 —— 而清册里那条早就在。

🔴 清册给的是 **Figma节点号，不是图片**。需要真SVG就用figma的 `download_assets` 按key导出（导出来会带一层Figma画板底色，记得去掉）。

## 8. 在UED WorkBuddy桌面版里产出时的约定

- 产物写在**项目目录根**：HTML文件会自动出现在右侧预览；一个页面一个文件，单文件、内联CSS与SVG、不依赖外网资源（Roboto用系统回落即可）。
- 每个页面都要覆盖状态：默认 / 加载 / 空 / 错误 / 禁用 / hover / focus，能用 `data-state` 或独立段落展示的就展示出来。
- 做完写一份 `交付说明.md`：页面结构、状态清单、用到的token对照、交互说明（每个决策带「为什么」）、未定项。这是「发给前端」时打包进交付包的核心文件。
- 文案中文与英文、数字之间不加空格（部门文案口径）。
