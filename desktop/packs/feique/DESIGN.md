> 这份是UED WorkBuddy桌面版随应用携带的飞鹊设计系统。做任何MIC / 飞鹊界面之前先读完这一页；
> 数值以本目录 `tokens.json` 为准，用法与判断以 `docs/飞鹊组件使用经验和规范.md` 为准（51KB，做视觉稿必读一遍）。
> **规范怎么用看 `docs/飞鹊设计规范-使用规则.md`** —— tokens.json 给的是值，那份给的是「什么时候用哪个」：

## 1. 字体与字号

- 字体只用 **Roboto**（CJK自动回落系统字体）。禁Noto Sans SC / PingFang显式声明。HTML里写 `font-family: Roboto, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;`
- 字重只有 **400 / 700**，700只给标题和一级信息。
- 🔴 **光写 `font-family: Roboto` 不够，必须同时有把 400/700 焊死的 `@font-face`。**
  浏览器拿到 `font-weight:400` 要去系统已装的 Roboto 家族里挑一张脸；装了多个静态 Roboto 的机器上
  **Chrome 会挑中 Roboto-Black(900)**，而中文回落 PingFang SC Regular(400) —— 同一行字里差 5 个字重档，
  看起来就是「英文数字明显比中文粗」。**这个 bug 是机器相关的**：没装 Roboto 的同事完全看不到它，
  所以同一份 HTML 在不同人机器上长得不一样。线上没这问题是因为线上写了 24 条 `@font-face` 把每档焊死。
  （2026-09-17 用 CDP `CSS.getPlatformFontsForNode` 实测。🔴 **光看 computed style 查不到这条**——
  它只告诉你「你要了 400」，不告诉你「浏览器给了 Black」。）
  🔴 **这条判据终端那套 skill 2026-07-27 就有了**（`figma-to-html-feique` §「字体」：「开工就 @font-face 内联锁字重，
  别靠 font-family 让系统挑」，还实测过「CSS 写 400、渲染出来是 700，墨水量多 63%」）。
  **它没进这份随包 DESIGN.md，于是客户端里整整两个月都在犯同一个错** —— 同一套飞鹊规范有两个维护源，
  这份是精简版，精简的时候把这条判据丢了。往这份里加东西时想一想：终端那边是不是已经有更细的一条。

  **在 UED WorkBuddy 里不用你动手**：应用会在预览刷新和交付打包两个时点自动把字体内嵌进 HTML
  （字体文件＝线上正在用的那两份，见 `fonts/INDEX.md`）。你要做的只有一件事：
  🔴 **别删页面里那段 `/* UW-FEIQUE-FONT */` 注释包起来的 CSS**。手写页面时照着 `fonts/INDEX.md` 加。
- Web字号阶梯（禁奇数，就近取偶）：`12 · 14 · 16 · 18 · 20 · 22 · 24 · 32 · 36`
  - **14px是默认**（正文、按钮、导航、输入框、标签、参数、面包屑）行高22
  - 16区块标题 / 24；18小屏标题 / 26；22副标题 / 28；24区块大标题 / 30；32大屏标题、价格 / 38；36页面主标题 / 42
  - 12只给真正不重要的注释（角标、底栏辅助说明）行高18
- 移动端阶梯：`10 · 12 · 14 · 16 · 18 · 20 · 22 · 24`（16是输入框主文字）
- 层级靠**颜色深浅**建立，不靠缩小字号。

## 3. 间距（4px网格）

水平间距严格只用7个token：`4 · 8 · 12 · 16 · 24 · 32 · 48`（xxs / xs / s / m / l / xl / 2xl）。
垂直间距优先用这7个，不够时允许20 / 28 / 36 / 40等4的倍数；禁5 / 10 / 15 / 25 / 30。
间距是层级信号：同级同间距，不同级拉开；不为塞内容压间距。

## 4. 圆角、描边、阴影

- 圆角实测：输入类 / 小控件 / 标签 **4** · 按钮 **6** · 表单卡片 **8** · 大卡片 **12** · 模态 **20** · 胶囊9999。外圆角 = 内圆角 + padding。圆角不随断点变。
- 描边宽度只有 **1 / 2**，描边一律inside。
- 阴影三级，要么全用要么全不用：
  - 1级（下拉、hover浮起）`0 5px 12px 4px rgba(0,0,0,.08), 0 3px 6px 0 rgba(0,0,0,.12), 0 1px 2px -2px rgba(0,0,0,.10)`
  - 2级（卡片hover、浮层）`0 9px 28px 8px rgba(0,0,0,.05), 0 6px 16px 0 rgba(0,0,0,.08), 0 3px 6px -4px rgba(0,0,0,.12)`
  - 3级（对话框、抽屉、通知）`0 12px 48px 16px rgba(0,0,0,.03), 0 9px 28px 0 rgba(0,0,0,.05), 0 6px 16px -8px rgba(0,0,0,.08)`

## 5. 按钮层级

实心红 `.btn-primary` → 主CTA（Send Inquiry等），**全页只有一个** · 次级 `.btn-secondary` → **白底 #222黑边黑字**（不是红描边——飞鹊按钮矩阵里根本没有「红描边」这个变体，`secondary+red` 的意思是「跟红主按钮配对的次级」）· 蓝描边 `.btn-secondary-blue` → 第三级（TM聊天）· 灰底灰边 `.btn-secondary-dark` → 工具性弱操作（筛选、排序）· 文字链 `.btn-link` → 页内跳转类动作。
浮层里的「确定 + 取消」＝ `.btn-primary` ＋ `.btn-secondary`，不能用灰按钮做取消。
🔴 2026-09-10反例：一页里2个实心红 ＋ 6个红描边 ＋ 一堆红tag，再加一个飞鹊没有的 `.btn-neutral`——每个色值都在表内，整页却不是飞鹊。**颜色合法不等于组件合法。**

**做法**：开工第一步先读 `docs/css/INDEX.md` —— 那是飞鹊28类组件的网页实现清单（砖表）。看这一页要用哪几个，就 `cat docs/css/{_reset,btn,inp,…}.css` 读出来（一律带上 `_reset.css`；28个全抄也才73KB），**把读到的内容原样贴进 `<style>`**。🔴 **别重定向到文件**（`> x.css`）——那样内容根本没进你眼里，只会凭印象重写出一版尺寸全错的。🔴 贴完**不许改里面的值**（高度/圆角/padding/字号/hover色都是定死的）。类名保持飞鹊的（前端拿到能一眼对上）。🔴 **不许自己另写一套 `.btn` / `.inp` / `.alert`，不许借飞鹊前缀造飞鹊没有的类**（`.btn-neutral`、`.btn-blue` 这种）。组件的高度、圆角、描边、字号以 `css/` 里的为准，本文件只管颜色与排版口径。
🔴 **砖表里没有的那25个是业务组件**（ProductCard八个变体、MIC Footer页脚、FilterSidebar、Supplier Ad、TM Bar、vo-header/nav/sider、mic-logo）——它们只有Figma、没有CSS实现，却恰恰是MIC真实页面的主力。清单带Figma key在 `INDEX.md` 末尾，用 `download_assets` 按key导出真资产；导不到就留灰色占位块并写明「待补真资产」，**别手画**（见第7节）。
🔴 就算用户没说「还原」，只要做的是MIC线上已有的页面类型（询盘、搜索、产详、发送成功页、登录注册…），先用chrome-devtools打开线上同类页看一眼，再动手——参照物先于灵感。

## 6. 视觉原则（死命令）

1. 统一性：混乱不是丰富。装饰能省则省，投影全用或全不用，同类交互反馈必须一致。
2. 层级三工具按优先级：颜色深浅 → 字重 → 字号。
3. 信息精简，空间感是层级的一部分。
4. 图标只用飞鹊295个SVG（查 `icons/INDEX.md`）；品牌认证标只用 `brand/` 里的18个（查 `brand/INDEX.md`）；**缺省图用 `sprites/` 里的 31 张，绝不自己画、也别再留空占位块**：写 `<div class="empty-img"><img data-feique-empty="图名" alt=""></div>`，src 由 UW 自动内嵌。挑哪张看 `sprites/INDEX.md`；🔴 供应商侧（VO 后台）用 `-supplier` 那套蓝的，买家侧用 `-buyer` 那套红的。
5. 🔴 **页面状态用根节点的类，绝不在页面里做 demo 控制条**（吉吉 2026-09-18 焊死）。
   要展示空 / 满 / 出错 / 未登录 / 加载这些态，写 `<body class="state-default">` ＋ CSS 里
   `body.state-empty .list{display:none}`，一页可以有任意多个 `state-*`。
   **不要**在页面里加「Demo 控制台 / 场景切换条」那种工具栏 —— 切换由流程控制台（预览栏「流程」那个独立窗口）负责，
   页面窗口保持 100% 是页面。这样交付给前端的 HTML 里一行演示代码都没有，
   而那些 `state-*` 类正好是前端要用的真实状态类。显隐一律 CSS 类控，**禁在元素上写内联 `display`**。
   状态的人话名和什么时候出现，写在同名的 `<页面>.说明.md` 里（流程控制台拿它跟代码比对）。

   🔴 **同一个文件里的抽屉 / 弹窗 / 浮层算「另一屏」，不是一个普通状态**（吉吉 2026-09-18：
   「PPC 营销助手主要在抽屉跳转，抽屉里的不同内容也是要展示的，这个也算页面」）。
   在 CSS 注释里声明一行，它就会在流程图上成为一个节点、在对照表上单独占一组列：

   ```css
   /* @视图 forecast 广告预测（抽屉） · 主页面点「广告预测」按钮打开 · .btn[data-open=forecast] */
   /* @态 forecast          填写中 · 刚打开，还没填全 */
   /* @态 forecast-result   出结果 · 点了「生成预测」之后 */
   ```
   声明之后 `state-forecast-*` 这一族就归它。三段：名字 · 怎么进来 · 入口选择器（第三段可选，
   写了会被门核验元素真不真的存在）。**名字里不要带 `·`** —— 那是字段分隔符。

   🔴 **跟状态正交、可以同时开着的那一维，用 `on-*`，不要拍平进 `state-*`**：
   ```css
   /* @叠加 oss OSS客服视角 · 只有客服看得到「行业平均 / 行业优秀」两列 */
   .ppc-oss{display:none}
   body.on-oss .ppc-oss{display:revert}   /* 用 revert 不写死 block：th/td/span 三种元素的默认值不一样 */
   ```
   拍平的代价是格子数翻倍，而且语义错了 —— 「出结果」和「出结果-OSS」会被读成两个并列的态，
   实际上后者是前者的一个切面。

   🔴 **派生出来的显示（标签页高亮、按钮文案）挂 MutationObserver 从根节点的类算**，
   别自己再存一份「现在是哪个态」的变量：控制台是在 iframe **外面**换类的，
   不触发页面里任何点击事件，存了变量就会出现「抽屉开着但标签没高亮」这种各说各话。
6. 「算对了」不等于「做对了」：写完自己在1240与375两个宽度下看一遍。
7. 🔴 品牌标识不许自己画，见第7节。手画的LOGO是最容易蒙混过关、也最丢人的一类错。

### 要放一个现成元素时，按这个顺序找

0. **做网页先看砖表 `docs/css/INDEX.md`**（§5b）—— 28类组件有现成CSS，挑要用的整段抄；清册是Figma坐标、不是网页实现。砖表里没有的那25个业务组件（产品卡/页头页脚/筛选侧栏/LOGO）才往下走第1步。
1. **组件用法清册 `COMPONENT-USAGE.md`** —— 🔴 **先读这份**。从 Figma 组件库逐页读出来的真值：
   48 个组件的 key／节点号／尺寸／**全部 variant 维度**／设计师写的说明。
   例：`MIC Footer Search` 有 1440/1366/1280/1024 四个断点（各高 280/280/280/316）；
   `date picker input/basic` 是 status×size×state×range 共 **108 个组合**；`popover` 有 **12 个方位** × 明暗两色；
   `form` 有 10 种场景（login/registration/inline/step form…）。
   🔴 **props／variant 是机器读的、永远准；description 是人写的、会过时**，打架时以 props 为准
   （`header-home` 的说明写断点 768/1024/1280/1366/1440，实际 props 是 1024/1280/1366/1440/**1920**）。
   🔴 **组件库页名里的 `✅` 和 `🤖` 都表示「已做完」，`❌` 表示「不需要做」**，不是没做。

## 8. 在UED WorkBuddy桌面版里产出时的约定

- 产物写在**项目目录根**：HTML文件会自动出现在右侧预览；一个页面一个文件，单文件、内联CSS与SVG、不依赖外网资源（Roboto用系统回落即可）。
- 每个页面都要覆盖状态：默认 / 加载 / 空 / 错误 / 禁用 / hover / focus，能用 `data-state` 或独立段落展示的就展示出来。
- 做完写一份 `交付说明.md`：页面结构、状态清单、用到的token对照、交互说明（每个决策带「为什么」）、未定项。这是「发给前端」时打包进交付包的核心文件。
- 文案中文与英文、数字之间不加空格（部门文案口径）。
